## Gemini Added Memories
- When adding a new Gradle dependency, first add it to the `gradle/libs.versions.toml` file, then run a Gradle sync/build to make the new alias available, and finally use the alias in the `build.gradle.kts` file.
- The user does not want me to automatically stage or push commits. They will handle that themselves.
- The user has explicitly stated to NEVER interact with git (staging, committing, or pushing) automatically. All git operations must be explicitly instructed by the user.
-  All generated methods **MUST** include a `// TODO: Test this method (Gemini)` to signify that it is an untested method generated by Gemini like so:
    ```swift
    func something { // TODO: Test this method (Gemini)
    
    }
    ```
- For every method that you modify that has a `//WORKING` comment, you are to remove the `//WORKING` and replace it with `// TODO: Test this method (modified by Gemini)` to signify that changes were made to the method and it needs to be tested again like so:
    ```swift
    func something { // TODO: Test this method (modified by Gemini)
    
    }
    ```
- All generated unit test methods **MUST** have the `// TODO: Pending Test` to signify that it is a pending test like so:
    ```swift
    func test_something { // TODO: Pending Test
    
    }
    ```
- For every unit test method that you modify that has a `// PASSED` comment, you are to remove the `// PASSED` and replace it with `// TODO: Pending Test (modified by Gemini)` to signify that changes were made to the method and it needs to be tested again like so:
    ```swift
    func test_something { // TODO: Pending Test (modified by Gemini)
    
    }
    ```
- All variables, classes, methods, etc., should be properly documented.
